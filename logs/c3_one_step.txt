The gate is evaluated on the held-out probe pool, which the preregistered C-3 metric names explicitly. Both pools are reported. Training-pool agreement at B = 4096 is a memorization metric by construction, since the student trains on every point being measured.
The same 20 student seeds (1000-1019) are used at every budget, so the budgets are paired: initialization and data order are identical and only the step count differs. These are the first 20 of the 50 seeds c2_no_chaining.py used for its B = 4096 reference, so the 1500-step arm is an exact re-run of 20 of C-2's own students rather than an independent redraw.

The one-step floor MOVED with the training budget.
The one-step floor is optimization-dependent, not an information limit. Consequences:
every decay claim must be reported against a budget-matched floor rather than against
generation 0 alone; the 1500-step choice becomes a reported parameter rather than an
implementation detail; and the C-2 escape generations (4, 7, 16) need re-checking,
since they are defined relative to a reference distribution that itself moves.

This does not invalidate C-2 — the chain still leaves the reference — but it changes
what the reference means.
